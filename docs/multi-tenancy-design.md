# new-api 组织功能设计

本文描述当前实现；产品行为见 [产品需求](multi-tenancy-prd.md)，升级与验证见 [交付说明](multi-tenancy-implementation.md)。

## 身份与资源归属

用户是全局登录身份。个人资源直接属于用户，`org_id=0`；查询兼容正式版升级后原有行的 `NULL`，不创建个人组织或回填个人资源。`Organization` 只表示团队，无类型枚举和配置版本号。

`OrganizationMember` 使用组织和用户联合唯一索引，记录 Owner/Admin/Member、状态和周期消费上限。组织的名称、Slug、Owner、状态、分组、钱包、累计用量、设置和预算周期保存在组织表。

共享资源使用 `ResourceScope{OrgID, UserID, AllMembers}`：个人查询必须绑定用户；组织默认绑定用户，经过权限校验才能读取全部成员。`TokenScope` 始终绑定创建者，组织 Owner/Admin 也不能读取或管理其他成员的 Key。平台查询通过独立接口授权，不把零组织 ID 当作全局通配符。

## 上下文与权限

控制台请求经 `UserAuth` 后，由 `OrganizationContext` 解析 `X-Org-Id`；没有请求头即为个人作用域。显式组织接口再要求有效组织上下文。Relay 根据 Token 的 `OrgId` 查验当前组织和成员，不接受客户端自行指定组织归属。

组织鉴权从数据库读取已提交的状态、分组和设置。Token 缓存只提供 Key 身份，不保存组织配置副本。模型限制取组织允许列表与 Key 限制的交集；价格、渠道和可用分组仍由平台控制。

Casbin 请求为 `sub, dom, obj, act`，策略为 `sub, dom, obj, act, eft`。组织 domain 为 `org:<id>`，通用策略使用 `*`。组织权限直接按当前成员角色的 `org-role:*` 主体检查，不使用角色继承。平台角色不隐式取得普通组织接口的访问权。

正式版旧策略由启动迁移转换到 domain 格式，因此旧、新二进制不得同时写入同一数据库。

## 组织采购与计费

平台的 `SubscriptionPlan` 增加受众 `personal/org/both` 和成员上限。订单保存组织、操作者和套餐快照；支付回调只信任持久化订单的归属。个人订阅使用原个人资金路径；组织请求由 `OrganizationFunding` 接入 `BillingSession`。

组织订阅优先消费，额度不足时根据 `AllowWalletOverflow` 决定是否使用组织钱包。组织订阅的分组升级和到期恢复作用于 `Organization.Group`，不修改成员个人分组。

`OrganizationCharge` 是按请求 ID 唯一的持久化计费凭据，记录预留量、组织、用户、Key、周期、订阅资金来源和最终状态。组织行锁将成员上限、Key 限额和资金变更串行化；MySQL/PostgreSQL 使用 `lockForUpdate`，SQLite 使用写事务。组织余额不依赖 Redis。

预留接口接收目标总额，重试只补足差额；最终费用可能超过预估，结算沿用补扣语义，但必须限制数值范围。退款与任务调整使用原始凭据和资金来源，订阅跨重置周期不向新周期退还旧额度。成员停用不阻断已预扣请求的结算或退款。

成员额度是共享池的消费上限，不是子钱包。预算周期开始后固定，没有订阅时按 UTC 自然月；预留与已结算费用都计入成员上限。组织预算用于告警，通知在事务中入队，再由后台投递，按周期和收件对象去重。

## 邀请与生命周期

邀请绑定已注册用户 ID，并保存用户名快照；用户名精确匹配，不依赖邮箱、邀请链接或邀请密钥。接受邀请时在组织锁内检查组织状态、成员关系、席位和邀请状态，成员与审计一起提交。

成员停用或移除会禁用其组织 Key 并失效 Token 缓存。恢复成员不会自动恢复 Key。Owner 转让必须由目标成员接受。Owner 自行停用和平台封禁使用不同状态，Owner 不能解除平台封禁。

删除组织前检查余额、有效订阅、待支付订单、未完成任务及预留凭据。软删除后由后台清理主库、独立日志库和 domain 策略。进程崩溃遗留的预留需结合上游执行结果对账，不能仅按时间自动退款。

## 前端隔离

Zustand 按登录用户持久化选中的组织 ID，权限和余额由服务端提供。`OrganizationBoundary` 验证成员关系、加载 context，并以用户和 epoch 为边界重建页面。

epoch 改变时，由 Boundary 的唯一订阅取消并清空 React Query 缓存；切换 Hook 只变更选择和处理导航。当前保留全量清理，避免未声明作用域的旧查询跨组织复用。HTTP 请求绑定发起时的组织和 epoch，过期响应丢弃；Playground 流在切换时关闭。

平台管理使用独立路由和查询入口，不因选中组织而改变权限。API 层通过 `skipOrganizationContext` 明确绕过组织头。

## 数据库与缓存

主库支持 SQLite、MySQL、PostgreSQL，日志可独立部署并支持 ClickHouse。组织资源的 `org_id` 建索引，组织 Slug、成员关系与请求凭据分别保持唯一性。

Token 使用 `token:org-v1:` 命名空间隔离正式版缓存。身份或权限变更仍使用现有缓存 fence。新建与正式版升级不创建废弃的组织类型、配置版本字段；本分支未发布的开发库不由启动流程自动删列，应在独立备份后重建测试数据。
